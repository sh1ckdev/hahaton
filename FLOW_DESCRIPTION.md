# Описание флоу работы приложения Rational Assistant

## 🎯 Цель приложения

Помочь пользователю избежать импульсивных покупок через:
- Период "охлаждения" перед покупкой
- Анализ финансовых возможностей
- Блокировку запрещённых категорий
- Регулярные напоминания о запланированных покупках

---

## 📋 Полный флоу работы приложения

### 1️⃣ **Первичная настройка (Onboarding)**

#### Шаг 1: Вход в систему
- Пользователь вводит свой `userId` (авторизация не требуется)
- Система создаёт профиль пользователя, если его ещё нет

#### Шаг 2: Финансовый профайл
**Модальное окно:** `FinancialProfileModal`

Пользователь указывает:
- **Зарплата в месяц** (`salary`) — основной доход
- **Сколько откладывает в месяц** (`savingsPerMonth`) — сумма ежемесячных накоплений
- **Текущие накопления** (`currentSavings`) — можно указать позже или обновить в профиле

> 💡 **Как обновить накопления:**
> - Перейти в **Личный кабинет** (меню пользователя → "Личный кабинет")
> - Найти блок "Текущие накопления"
> - Нажать на иконку редактирования (✏️) рядом с суммой
> - Ввести новую сумму и нажать ✓

#### Шаг 3: Расширенная анкета (опционально)
**Модальное окно:** `ExtendedProfileModal`

6 шагов анкеты:
1. **На что тратит больше всего** — выбор категорий трат
2. **Импульсивные категории** — категории, где часто совершаются импульсивные покупки
3. **Финансовые цели** — цели с приоритетом и стоимостью (создаются в системе целей)
4. **Категории, мешающие целям** — категории, которые отвлекают от финансовых целей
5. **Процент отложений** — какой процент дохода откладывается
6. **Есть ли долги** — наличие кредитов/долгов

После заполнения анкеты:
- AI анализирует ответы и предлагает категории для blacklist
- Финансовые цели сохраняются в систему целей

#### Шаг 4: Настройка Blacklist (запрещённые категории)
**Модальное окно:** `InitialBlacklistModal`

- Пользователь видит предложенные AI категории
- Может добавить/удалить категории вручную
- Категории из blacklist будут блокироваться при добавлении покупок

---

### 2️⃣ **Настройка правил охлаждения**

**Страница:** `/goals` → раздел "Правила охлаждения"

Пользователь настраивает **диапазоны охлаждения** в зависимости от суммы покупки:

Пример:
- **до 15,000 ₽** → 1 день
- **от 15,000 до 50,000 ₽** → 7 дней (неделя)
- **от 50,000 до 100,000 ₽** → 30 дней (месяц)
- **от 100,000 ₽** → 90 дней

> 💡 Правила можно настроить для любого количества диапазонов, потолка нет.

---

### 3️⃣ **Настройка уведомлений**

**Страница:** `/notification-settings`

#### Частота уведомлений:
- **Ежедневно** — раз в день
- **Еженедельно** — раз в неделю
- **Ежемесячно** — раз в месяц
- **Кастомное время** — можно указать в секундах/минутах/часах/днях

#### Каналы уведомлений:
- **В приложении** (UI) — уведомления в интерфейсе
- **Email** — требует настройки SMTP (см. `NOTIFICATION_SETUP.md`)
- **Telegram** — требует создания бота и подключения через `/start userId`

#### Индивидуальные настройки для каждого товара в вишлисте:
- Использовать глобальные настройки
- Включить уведомления с индивидуальным интервалом (1, 3, 7, 14, 30 дней)
- Отключить уведомления для конкретного товара

---

### 4️⃣ **Добавление покупки в вишлист**

#### Способ 1: Через чат-ассистента
**Компонент:** `ChatPanel`

Пользователь отправляет:
- Ссылку на товар (например, с Wildberries, Ozon и т.д.)
- Или описание товара в свободной форме

**Что делает система:**
1. **Парсинг ссылки** (если это ссылка):
   - Извлекает название товара
   - Извлекает цену
   - Определяет категорию (через AI)

2. **Анализ покупки:**
   - Проверяет, не находится ли категория в blacklist
   - Если в blacklist → блокирует покупку, рекомендует не совершать
   - Если не в blacklist → продолжает анализ

3. **Расчёт периода охлаждения:**
   - Определяет диапазон по цене (из правил охлаждения)
   - Если включена функция "Учитывать текущие накопления" (`considerSavings`):
     - Проверяет, достаточно ли накоплений для покупки
     - Если недостаточно → рассчитывает, через сколько дней можно будет купить
     - Учитывает `savingsPerMonth` и `minReserveRatio` (минимальный резерв, по умолчанию 50%)
   - Устанавливает `cooldownUntil` — дату, когда можно будет купить

4. **Сохранение в вишлист:**
   - Статус: `planned`
   - Сохраняется `cooldownUntil` и `comfortableFrom` (когда покупка станет комфортной с учётом накоплений)

#### Способ 2: Вручную через модальное окно
**Компонент:** `AddPurchaseModal`

Пользователь вводит:
- Название товара
- Цену
- Категорию (выбор из списка)
- URL товара (опционально)

Система применяет те же правила анализа и расчёта периода охлаждения.

---

### 5️⃣ **Управление вишлистом**

**Страница:** `/wishlist` или раздел на главной странице

#### Действия с товарами:
- **Редактировать** — изменить название, цену, категорию
- **Настройки уведомлений** — индивидуальные настройки для каждого товара
- **Отметить как купленное** — статус меняется на `purchased`
- **Отменить** — статус меняется на `canceled`, товар удаляется из вишлиста

#### Отображение информации:
- Название и цена
- Категория
- Дата окончания периода охлаждения (`cooldownUntil`)
- Дата, когда покупка станет комфортной (`comfortableFrom`) — если включена функция учёта накоплений

---

### 6️⃣ **Система уведомлений**

**Сервис:** `notificationService.js`

#### Как работает:
1. **Планировщик** запускается каждые 5 секунд (для тестирования, можно изменить)
2. **Для каждого пользователя:**
   - Проверяет, включены ли уведомления (есть активные каналы)
   - Проверяет частоту уведомлений (глобальную или индивидуальную для товара)
   - Проверяет, прошёл ли минимальный интервал с последнего уведомления

3. **Для каждого товара в вишлисте:**
   - Статус: `planned`
   - Не заблокирован категорией (`blockedByCategory !== true`)
   - Категория не в blacklist
   - Уведомления не отключены для товара (`notifyEnabled !== false`)
   - Проверяет интервал уведомлений (глобальный или индивидуальный)

4. **Создание уведомлений:**
   - **UI-уведомление** — создаётся в базе данных, отображается в интерфейсе
   - **Email-уведомление** — отправляется через SMTP (если настроено)
   - **Telegram-уведомление** — отправляется через бота (если настроено)

5. **Содержание уведомления:**
   - Текст: "Ты всё ещё хочешь купить [название] за [цена]?"
   - Ссылка на страницу вишлиста (`/wishlist`)
   - Ссылка на товар (если указан URL)

---

### 7️⃣ **Финансовые цели**

**Страница:** `/goals`

#### Создание цели:
- Название
- Стоимость
- Приоритет (1-10)
- Описание (опционально)

#### Использование:
- Цели учитываются при анализе покупок
- AI может рекомендовать не совершать покупку, если она мешает достижению цели
- Цели отображаются на главной странице в карусели

---

### 8️⃣ **Синхронизация с банком (опционально)**

**API Endpoint:** `POST /api/users/:userId/bank-sync`

Позволяет обновить финансовые данные:
- `salary` — зарплата
- `currentSavings` — текущие накопления
- `savingsPerMonth` — откладываемая сумма в месяц
- `spentThisMonth` — потрачено в этом месяце

> 💡 Это может быть использовано для интеграции с банковскими API в будущем.

## 🔄 Типичный сценарий использования

1. **Пользователь заходит в приложение первый раз:**
   - Указывает зарплату и сумму отложений
   - Заполняет расширенную анкету (опционально)
   - Настраивает blacklist категорий

2. **Настраивает правила охлаждения:**
   - Устанавливает диапазоны для разных сумм покупок

3. **Настраивает уведомления:**
   - Выбирает частоту и каналы (UI, Email, Telegram)

4. **Хочет купить что-то:**
   - Открывает чат-ассистента или модальное окно добавления покупки
   - Отправляет ссылку или описание товара
   - Система анализирует покупку:
     - Проверяет blacklist
     - Рассчитывает период охлаждения
     - Рассчитывает комфортную дату покупки (если включён учёт накоплений)
   - Товар добавляется в вишлист со статусом `planned`

5. **В течение периода охлаждения:**
   - Пользователь получает уведомления (согласно настройкам)
   - Может открыть вишлист и посмотреть все запланированные покупки
   - Может отменить покупку или отметить как купленную

6. **После периода охлаждения:**
   - Пользователь может принять решение: купить или отменить
   - Если купил → отмечает как `purchased`
   - Если передумал → отменяет (`canceled`)

## 📊 Структура данных

### User (Пользователь)
```javascript
{
  userId: String,              // Уникальный ID пользователя
  salary: Number,              // Зарплата в месяц
  currentSavings: Number,      // Текущие накопления
  savingsPerMonth: Number,     // Откладываемая сумма в месяц
  considerSavings: Boolean,     // Учитывать накопления при расчёте
  minReserveRatio: Number,     // Минимальный резерв (0.5 = 50%)
  notificationSettings: {
    frequency: String,          // daily/weekly/monthly/custom
    customFrequencyMs: Number,  // Кастомный интервал в миллисекундах
    channels: [String],         // ["ui", "email", "telegram"]
    emailSettings: {
      enabled: Boolean,
      email: String
    },
    telegramSettings: {
      enabled: Boolean,
      chatId: String
    }
  },
  extendedProfile: {
    topSpendingCategories: [String],
    impulsiveCategories: [String],
    blockingCategories: [String],
    savingsPercentage: Number,
    hasDebts: Boolean
  }
}
```

### Purchase (Покупка)
```javascript
{
  userId: String,
  title: String,               // Название товара
  price: Number,               // Цена
  category: String,            // Категория
  status: String,             // planned/purchased/canceled
  cooldownUntil: Date,        // Дата окончания периода охлаждения
  comfortableFrom: Date,       // Дата, когда покупка станет комфортной
  blockedByCategory: Boolean,  // Заблокирована категорией
  notifyEnabled: Boolean/null, // Индивидуальные настройки уведомлений
  notifyEveryDays: Number,     // Интервал уведомлений для товара
  lastNotifiedAt: Date,        // Последнее уведомление
  url: String                  // Ссылка на товар
}
```

### CooldownRule (Правило охлаждения)
```javascript
{
  userId: String,
  minPrice: Number,            // Минимальная цена диапазона
  maxPrice: Number,            // Максимальная цена диапазона (null = без ограничений)
  days: Number                 // Количество дней охлаждения
}
```

## 🎨 Основные страницы и компоненты

### Страницы:
- `/` — Главная страница (Dashboard)
- `/login` — Вход (ввод userId)
- `/profile` — Личный кабинет
- `/goals` — Управление целями и правилами охлаждения
- `/wishlist` — Страница вишлиста
- `/blacklist` — Управление запрещёнными категориями
- `/notification-settings` — Настройки уведомлений

### Модальные окна:
- `FinancialProfileModal` — Настройка финансового профиля
- `ExtendedProfileModal` — Расширенная анкета
- `InitialBlacklistModal` — Первичная настройка blacklist
- `AddPurchaseModal` — Добавление покупки
- `PaymentConfirmationModal` — Подтверждение транзакции (SSE)
- `ChatPanel` — Чат с AI-ассистентом

## 🔧 Технические детали

### Backend:
- **Node.js + Express**
- **MongoDB** — база данных
- **Swagger/OpenAPI** — документация API
- **Nodemailer** — отправка email
- **Telegram Bot API** — отправка уведомлений в Telegram

### Frontend:
- **React + Vite**
- **MobX** — управление состоянием
- **React Router** — маршрутизация
- **Tailwind CSS** — стилизация

### AI/ML:
- **OpenRouter API** — для анализа покупок и генерации советов
- Категоризация товаров
- Генерация blacklist на основе анкеты
- Генерация советов по покупкам

---

## 📝 Важные замечания

1. **Авторизация не требуется** — пользователь идентифицируется только по `userId`
2. **Период охлаждения** рассчитывается автоматически на основе:
   - Цены товара (диапазоны охлаждения)
   - Текущих накоплений (если включена функция учёта)
3. **Уведомления** работают только для товаров со статусом `planned`
4. **Blacklist** блокирует добавление товаров из запрещённых категорий
5. **Финансовые цели** учитываются AI при анализе покупок
